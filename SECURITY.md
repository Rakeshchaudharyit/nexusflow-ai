# Security reporting

Do not post credentials, session cookies, customer data or exploit details in public issues.

No private reporting channel is configured by this checkout. Before publication, the owner should enable GitHub private vulnerability reporting and verify that the repository Security tab offers it. If unavailable, request a private reporting channel without disclosing the vulnerability publicly.

Rotate exposed credentials immediately; deleting a file does not revoke a credential or remove Git history. Demo identities are synthetic and demo passwords must be supplied privately through environment variables. Never reuse them in production.

This locally validated portfolio project has no published supported release or security response SLA. See [production gates](docs/production-checklist.md).
